## 1. P0 — 可用性杀手（外部用户必踩）

### P0-1 非 `pppoe-wan` / 无 IPv6 的路由器上，引擎一条转发都不起

* 位置：`root/etc/socat-boot.sh:210-212`（`get_ipv6`）、`343-357`（主循环）

```sh
get_ipv6() { ip -6 addr show pppoe-wan 2>/dev/null | grep 'scope global' | ...; }
...
if [ -z "$IPV6" ]; then
    log "WARN: No IPv6, retry in 30s"
    sleep 30
    continue          # ← 跳过了 reconcile / check_health / pet_watchdog / sync_firewall
fi
```

* 后果：WAN 是 DHCP/静态（`wan`、`eth0`、`wwan`）或全局 IPv6 关闭时 → **连 IPv4 转发都不工作**，UI 里全部规则显示 `down`；同时每 30s 一条 WARN 日志（≈2880 条/天，把 logread ring buffer 冲掉）。
* 证据：Router 自己是 pppoe-wan+IPv6，所以这里"侥幸正常"（日志中 0 条 `No IPv6`）；代码路径上其它场景 100% 复现。
* 修复：IPv6 探测改为"遍历所有接口取 global 地址（或从默认路由推导设备）"；无 IPv6 时只跳过 IPv6 系监听，**reconcile 照常执行**；日志只在状态翻转时打一次。

### P0-2 `check_wg_dnat` 硬编码 WG 51820 → 别人的路由器每分钟重载 fw4 + 清 conntrack

* 位置：`root/etc/socat-boot.sh:233-240`、调用点 `349-351`（每 4 个循环 ≈ 60s 一次）

```sh
if ! nft list chain inet fw4 dstnat_wan 2>/dev/null | grep -q '51820.*dnat'; then
    log "WG 51820 DNAT rule missing, reloading fw4"
    /sbin/fw4 reload 2>/dev/null
    echo f > /proc/net/nf_conntrack 2>/dev/null
```

* 实测证据（只读、无副作用）：`nft list chain inet fw4 no_such_chain` → `Error: No such file or directory` → grep 必不匹配 → **分支必走**。
* 后果：任何没有"WG 51820 DNAT"规则的路由器（= 几乎所有外部用户）**每 60 秒**：① 重载防火墙；② **清空连接跟踪表** → 所有 NAT 会话断流（Web 掉线、VoIP 断、游戏/下载中断）。这是把自己家里的配置写死进了公开包。
* 修复：整个函数按 UCI 驱动（仅当 `firewall` 里真的存在 51820 DNAT 时才守护），默认关闭；更彻底的做法是删掉——防火墙自愈不属于 socat 转发器的职责。

### P0-3 `fix_ipv6_route` 硬编码 `dev pppoe-wan`，且是为特定 ISP 补路由的个人 hack

* 位置：`root/etc/socat-boot.sh:214-231`

```sh
ip -6 route add 2000::/3 via $GW dev pppoe-wan metric 1024 2>/dev/null
```

* 后果：① 设备上没有 `pppoe-wan` → `ip` 直接失败（被 `2>/dev/null` 吞掉）；② 若设备上恰好有 `pppoe-wan` 但不是默认出口，可能写入错误路由；③ 多默认路由时 `head -1` 取到的网关未必是期望的那个；④ 这种行为本身（静态补 2000::/3）应为**可选项**，不能默认开。
* 修复：设备名从默认路由推导；功能收敛成一个 UCI 开关，默认关闭。

## 2. P1 — 功能/逻辑 bug

### P1-1 UDP 永远只有 IPv4 监听；`family=6` 对 UDP 是"静默说谎"

* 位置：`root/etc/socat-boot.sh:126-133`（TCP 分支有 family 处理，else 分支没有）
* 实测矩阵（在 Router 上跑真实 `emit_section`）：

| proto | family | IPv6 可用 | 实际生成 |
| --- | --- | --- | --- |
| udp | `6` | 是 | `UDP-LISTEN:5000,fork UDP4:…` ❌ 选"仅 IPv6"拿到的是 IPv4 |
| udp | `''` | 是 | 只有 IPv4 ❌（TCP 默认是双栈，UDP 不是，语义不一致） |
| tcp | `6` | 否 | **一行都不输出** ❌ 规则 enabled 却没有任何 worker，UI 只显示 down 且不给原因 |
| tcp | `x`(脏数据) | 是 | 当成"双栈" ❌ `family` 无校验 |
| tcp | `''` | 是 | v4+v6 两条 ✓ |
| tcp | `4` | 是 | 仅 v4 ✓ |

### P1-2 起进程失败完全静默 → UI 只能说 "down"，永远看不到原因

* 位置：`root/etc/socat-boot.sh:193-198` `$c >/dev/null 2>&1 &`
* 端口被占、端口越界（见 P1-3）、目标写错等，socat 的报错全进 /dev/null；每 15s 静默重试一次。
* 修复：stderr 重定向到 per-rule 日志，`status` 增 `error` 字段，UI 在 down 行给 tooltip/原因。

### P1-3 引擎侧端口无范围校验；`family`、`sid` 无校验；UI 侧 IP 无 datatype

* 引擎：`socat-boot.sh:99-100` 只查"是不是数字"；实测 `listen_port=99999`、`listen_port=0`、`dest_port=99999` 全部通过并生成命令行（socat 起不来 → 静默 down）。
* `sid`：`socat-boot.sh:298-301` 的 `restart-rule` 与 `emit_section` 中 `$sec` 无引号使用 → 可向 `uci` 注入参数（后端有 `shellquote` 挡 shell，UCI 层没有）。
* UI：`socat-reforged.js:605-608`（`dest_ip`）、`637-643`（`proxy_server`）**没有 `datatype`**，任意字符串可落库 → 与 P1-3 引擎侧叠加后会出现 `dest_ip` 含 `*` 时 glob 展开等怪事。

### P1-4 引擎会杀掉"别人的 socat"

* `socat-boot.sh:170-188`：凡 cmdline 含 `LISTEN:` 且不在 desired 集合里的进程，一律 kill；`check_health()` `262-264`、`ctl:24`、`init.d:19-21` 都是 `killall socat`。
* 用户自己手工起的 socat 转发、或另一个 socat 管理插件，会被这个引擎接管/杀掉。
* 修复：给自己的 worker 打标记，例如 `env SOCAT_REFORGED=1 /usr/bin/socat …`，进程识别改为读 `/proc/<pid>/environ`；reconcile 的 kill 也限定在白名单内。

### P1-5 `restart` 语义错误：绕过 procd，Stop 之后按 Restart 会留下"半活"状态

* `socat-reforged-ctl:27-33`：restart = `killall` + 直接跑 `/etc/socat-boot.sh reconcile`，完全不碰服务。
* 若用户先按过 Stop（`ubus service delete`），再按 Restart → worker 起来了，但**引擎 loop 没起**：没有 reconcile、没有 heartbeat、没有防火墙同步。UI 同时显示 "engine stopped" 和所有规则 "listening"，自相矛盾，且之后任何配置变化都不生效。
* 修复：restart 走 `/etc/init.d/socat-reforged restart`（stop→start）。

### P1-6 `sync_firewall` 在 `fw4 check` 失败时会和自己打架（永久 churn）

* `socat-boot.sh:68-77`：check 失败 → 删规则 + `uci commit`，但**不写 SIGFILE** → 下一周期发现签名不同 → 又加回来 → 又 check 失败 → 又删…… 每 15s 一次 `uci commit firewall` + 一条 WARN，永不停止。
* 附带：用户手工删掉我们的 fw 规则后**不会**被修复（SIGFILE 还在，签名匹配就直接 return）。
* 修复：失败也写一个带失败标记的签名 + 指数退避（失败后间隔拉长到分钟级）；签名里加入"规则是否真实存在"的校验。

### P1-7 后端在 `/etc/config/socat` 缺失/损坏时整体抛错 → 整个 UI 变 "unknown"

* `luci.socat-reforged.uc:138` `uci.load('socat')` 无保护；`uci.get` 无默认值保护时会抛 ucode 异常，`status` 调用直接失败，前端 `catch` 把所有规则显示为 unknown。
* 修复：`exists()` 预检 + try/catch，返回带 `error` 的 status 对象。

### P1-8 `engine_state` 的 pgrep 兜底会谎报 engine 活着

* `luci.socat-reforged.uc:121-128`：hb 缺失但有 socat 进程 → `age=0` → UI 显示 "reconciled 0s ago"、engine running。
* 实测 Router 上 27 个 worker 的 PPid 全是 1（都是历史 loop 的后代），正好会命中这个兜底：loop 明明死了却显示正常。
* 修复：`running` 以 loop 进程存在为准（`pgrep -f /etc/socat-boot.sh`），pgrep 只用于 worker 计数。

### P1-9 卫生与锁

* `socat-boot.sh:158,200` 的 `trap` + 手动 `rm -rf "$lockdir"` 双清理，若在 `echo $$ > pid` 之前被打断会留下无 pid 的锁（有 3 次重试兜底，风险低）。
* `reconcile` 用的 `/tmp/socat-desired` 等是**固定路径**（多进程/本地符号链接面），建议 `mktemp`。
* `heartbeat()` (`:283-284`) 的写非原子。

## 3. P2 — 性能与健壮性

### P2-1 每 15s 约 200 次 fork、约 2s CPU —— 只是为了发现"什么都没变"

* 实测数据（Router，x86_64）：300 次混合 fork = **2.96s**；一轮 `reconcile + sync_firewall + heartbeat` ≈ **2.1s**，循环周期 15s → **单核 13% 常驻**，纯空转。
* 构成：`emit_section` 每条规则 10 次 `uci -q get` × 15 条 = 150 次；`sync_firewall` 每条 3 次 = 45 次；加 `uci show`/`pgrep`/`nft`。
* 低端 mips/ath79 路由器单次 fork 成本高 3~5 倍 → **持续 40~60% CPU**，白烧 CPU 和电，还会拖累转发性能。
* 修复方向：① 一次 `uci show` 解析出所有选项（1 次 fork 替代约 200 次）；② desired 计算后与缓存比对，未变直接跳过；③ 主循环改事件驱动（ucitrack 触发 + 60s 兜底），把 15s 轮询拉长。

### P2-2 日志噪声：`HEALTH` 每 60s 一条 × 24/7

* `socat-boot.sh:365-371`。logread ring buffer 被健康日志刷掉，真正的 WARN/CRIT 被淹（实测日志里 HEALTH 占绝大多数）。
* 修复：默认关闭，`uci get socat.reforged.debug` 打开；且只在状态变化时输出。

### P2-3 内存健康的 CRIT 分支无退避，会 flap

* `socat-boot.sh:256-272`：低于 10% 就 `killall socat` 后立即全量 reconcile；内存持续低位时会反复重启。
* 另外 `MemAvailable * 100 / MemTotal` 的阈值语义在小内存机器上偏松（128MB 机器要掉到 12.8MB 才触发）。建议：绝对下限（如 4MB）+ 百分比双条件 + 失败计数退避。

### P2-4 防火墙端口列表无聚合

* `socat-boot.sh:50-65`：每条规则一个 `add_list dest_port`，几十条规则就是几十个端口；fw4 check/reload 变慢。可合并连续端口为 range（`1935-1936`）。

### P2-5 UI 侧

* `socat-reforged.js:657` 的 `enable` onchange 用 `setTimeout(50ms)` 后再 recount，是猜时序；应直接同步。
* 导入（`handleImport` `380-390`）不做任何校验/预检就 `uci.add`，脏数据可直接落库（与 P1-3 叠加）；且导入是"追加"不是"合并/替换"，无冲突预览。
* 冲突检测只覆盖"两个规则抢同一个 proto:port"，没有覆盖"和系统里别的服务抢端口"（dnsmasq/UPnP/DHCP 等）。
* `checkDirty` 用 `tr.querySelector('input[type="checkbox"]')` 找行内开关，依赖 DOM 结构；主路径其实由 `editable` 选项的 `uci.set` 覆盖，但这条兜底是脆的。

### P2-6 其它

* `KEEPALIVE` 只对 TCP 生效，UDP 无参数；`reuseaddr` 默认 1 已处理 ✓。
* `ctl stop`/`init.d stop_service` 都是 `killall`（见 P1-4），且 `stop` 之后 fw 规则仍留在 UCI 里（无害但不整洁）。
* `/proc/net` 解析（`lu.socat-reforged.uc:57-79`）正确，但 UDP 只要有任何进程占该端口就算 listening（含误报）。

## 5. 一句话总结

> **这个包对外发布的可用性取决于"用户的路由器长什么样"**：只要不是 `pppoe-wan` + 全局 IPv6 + 恰好有 WG 51820 DNAT 的组合，就会出现"完全不干活"（P0-1）、"每分钟清空连接跟踪"（P0-2）、"补错路由"（P0-3）三种后果之一。这三件事修掉，这个包才真正配得上"self-contained / out-of-the-box"。剩下的是一个**偏高的常驻 CPU 开销**（P2-1）和**可观测性缺失**（P1-2：进程起不来永远不告诉你为什么）。
