# luci-app-socat-reforged 后续升级与提升改进方案

*配套文档：`AUDIT-2026-10-13.md`（审计发现）。本文按"先救命、再正确、后性能、再产品化"的四段式路线给出可执行方案，每项含改动要点与验收标准。版本策略不变：暗修不发版，用户说「发版」才动 `PKG_VERSION`（下一个 = `V3`）。*

---

## 阶段 0 —— 开箱即用（必做，成本低收益最大）

> 目标：装上就能用，不管用户是什么 WAN 类型、有没有 IPv6、有没有 WG。

**0-1 IPv6 探测泛化 + 无 IPv6 也正常 reconcile**（对应 P0-1）
- `get_ipv6()` 改为：先取默认路由设备（`ip -6 route show default` 首条），从该设备取 `scope global` 地址；失败再遍历 `ip -6 addr` 全部 global 地址；都失败返回空。
- 主循环删掉"没 IPv6 就 continue"：IPv6 为空时 `reconcile` 照跑（TCP6/UDP6 行自然不生成），只去打点日志。
- 日志降频：用 `/var/run/socat-reforged.v6` 记住上一次的状态，只在翻转时 log。
- 验收：临时把 `get_ipv6` 强制返回空，`reconcile` 仍能让 IPv4 规则 listening；logread 里 `No IPv6` ≤ 1 条/小时。

**0-2 移除/收编 `check_wg_dnat`**（P0-2）
- 首选**直接删除**该函数（防火墙自愈不是本插件职责，用户有 fw4/网络向导）。
- 若用户坚持要保留这个"看护"能力：改为按 UCI 驱动 —— 只有 `firewall` 配置里真的存在 `dest_port=51820` 且 `target=DNAT` 的规则时才检查，否则整个函数 no-op；并且检查失败只 log 一次 + 退避到 10 分钟，绝不清 conntrack。
- 验收：在无 WG 的路由器上跑 10 分钟，`logread` 无 `WG 51820` 记录、`/proc/net/nf_conntrack` 无反复 flush（用 `echo f` 前后 conntrack 计数对比）。

**0-3 `fix_ipv6_route` 改为 opt-in + 设备名推导**（P0-3）
- 新增 `socat.reforged.fix_v6_route`（默认 `0`）；开启时设备名从默认路由推导（不再写死 `pppoe-wan`），并用 `ip -6 route replace` 代替 del+add。
- UI 增加一个"高级/实验"折叠区放开关。
- 验收：默认关闭时日志与行为与现在完全一致（除不再有那条路由操作）；开启时路由正确指向默认出口设备。

**0-4 UDP 的 family 语义与 TCP 对齐**（P1-1）
- `emit_section` 的 UDP 分支补 `UDP6-LISTEN`；`family=6`  strictly 只出 v6，`family=''` 出 v4+v6。
- `family=6` 且无可用 IPv6 → 打一条 WARN（说明规则暂时无监听）。
- 验收：跑一遍 0-4 行为矩阵表（udp×family×有无v6 共 6 种），输出与表格一致。

**0-5 校验补齐**（P1-3）
- 引擎：端口统一 `case in ''|*[!0-9]*) skip;; esac` + `[ "$p" -ge 1 ] && [ "$p" -le 65535 ]`；`family` 只允许 `''|4|6`；`sid` 只允许 `[A-Za-z0-9_]+`，其余直接 return。
- UI：`dest_ip` 加 `datatype = 'or(ipaddr, ip6addr)'`，`proxy_server` 同；`listen_port`/`dest_port`/`proxy_port` 保持 `port`（自带 1-65535）。
- 验收：UCI 里手写 `listen_port=99999` / `family=xx` / 脏 sid，引擎只 WARN 不生成进程。

**0-6 `restart` 改走服务**（P1-5）
- `socat-reforged-ctl restart` → `/etc/init.d/socat-reforged restart`（必要时先 `stop` 再 `start`）。
- 验收：先按 Stop、再按 Restart，UI 应显示 engine running 且所有规则 listening；`/etc/socat-boot.sh` loop 进程唯一。

**0-7 修 `sync_firewall` 自我打架**（P1-6）
- `fw4 check` 失败时写"失败签名"并退避（指数，上限 10 分钟）；成功才写真签名。
- 签名内容改为"期望规则内容 + 规则实际存在性"，这样用户手工删规则也能自愈。
- 验收：人为把 firewall 配置改坏（`fw4 check` 失败），观察 5 分钟：`uci commit firewall` 次数有限、日志有退避痕迹；恢复后自动修好。

**0-8 只杀自己的 worker**（P1-4）
- 生成命令行改为 `env SOCAT_REFORGED=1 /usr/bin/socat …`；reconcile/kill 路径改为读 `/proc/<pid>/environ` 过滤标记。
- `ctl stop` / `init.d stop_service` / `check_health` 的 `killall socat` 改为按标记精准 kill。
- 验收：手动起一个 `socat TCP-LISTEN:19999 …`，跑 3 个 reconcile 周期，`19999` 的进程仍活着；自己管理的规则照常 diff。

## 阶段 1 —— 正确性与可观测性

**1-1 per-rule 错误上报**（P1-2，体验提升最大的一项）
- 引擎起进程时把 stderr 追加到 `/var/run/socat-reforged.err.<sid>`（或统一一个文件按行记 sid + 时间）。
- 后端 `status` 每规则返回 `{ status, error?: 首行错误 }`；UI 在 down 行的 title/单元格显示原因（如 `address already in use`）。
- 验收：制造端口冲突，UI 该行显示 `down — address already in use`。

**1-2 后端容错**（P1-7/P1-8）
- `uci.load('socat')` 前 `exists()` 检查，try/catch 包裹；`status` 增加顶层 `error` 字段。
- `engine.running` 改用 loop 进程存在性判定；`workers` 继续用 pgrep。
- 验收：`mv /etc/config/socat /tmp/` 后打开页面，显示"无配置"而不是一片 unknown；恢复后正常。

**1-3 卫生项**（P1-9）
- `/tmp/socat-*` 改 `mktemp`；heartbeat 改"写临时文件 + `mv`"原子替换；锁的 `echo $$ > pid` 提前到 mkdir 之后立刻执行（现状已如此，补一句注释说明）。
- 验收：`sh -n` 通过；连续 10 个周期无残留 `/tmp/socat-*`、无僵尸进程。

**1-4 内存健康退避**（P2-3）
- 双条件：`MemAvailable < 4MB` **或** 百分比 < 10%，且连续 2 次命中才动手；连续失败做退避。
- 验收：mock 小内存不好造，至少把退避逻辑单测/逻辑走查通过。

## 阶段 2 —— 性能与工程化（P2-1 是重点）

**2-1 单次 `uci show` 解析替代 ~200 次 fork**
- 新增 `load_rules()`：`uci show socat` 一次输出，用 `sed/awk` 解析成 `key=value` 的临时文件或 shell `eval`（注意引号安全：值可能含空格，用 `while IFS= read` + cut 解析更稳）。
- `emit_section` 从该结构取值；`sync_firewall` 复用同一份。
- 预期收益：每周期 fork 从 ~200 次降到 ~10 次，CPU 从 13% → 1% 以内（x86_64 实测基准），低端 mips 上更明显。

**2-2 desired 缓存 + 事件驱动**
- 把"本次 desired 内容"写入 `/var/run/socat-reforged.desired`，与上次比对，相同则**整个 reconcile 跳过**（连 pgrep 都不做）。
- 主循环：正常 15s（仅做 IPv6 变化检测这类廉价检查，或拉到 30~60s），**ucitrack 触发器**负责 Save&Apply 后的即时 reconcile（已有 `socat-reforged-reload`，新增一个 `uci-reload-state` 式的触发点更稳）。
- 周期里 `check_wg_dnat`/`fix_ipv6_route` 跑 60s 级即可，且默认关。

**2-3 日志分级**（P2-2）
- `DEBUG` 开关（`socat.reforged.debug`，UI 高级区）；HEALTH 默认不打；WARN/CRIT 保留但加"抑制"（同一消息 5 分钟内不重复）。
- 验收：默认配置跑 1 小时，logread 里本插件 ≤ 几条。

**2-4 fw 端口聚合**（P2-4）
- 排序后把连续 ≥3 个端口合成 `start-end` 的 `add_list`（fw4 支持 range）。
- 验收：Router 现有 12 个 tcp 端口 → 规则里变成几条 range，`fw4 check` 通过、WAN 仍通。

**2-5 UI 时序/导入健壮化**（P2-5）
- `enable` onchange 去掉 setTimeout；导入前做字段白名单+校验预览（列表显示将新增的 N 条、跳过的 M 条及原因），确认后才 `uci.set`；提供"替换全部"选项。
- 验收：导入一个含脏数据（缺 listen_port、proto 非法）的 JSON，提示"跳过 2 条：listen_port 缺失"，不落脏库。

## 阶段 3 —— 产品化升级（按性价比排序）

| # | 能力 | 说明 | 成本 |
| --- | --- | --- | --- |
| 3-1 | **每规则错误/健康详情** | down 的原因、最后成功 reconcile 时间、当前连接数/峰值、累计重启次数 | 小 |
| 3-2 | **系统级端口冲突检测** | 不只"规则 vs 规则"，还和 `netstat`/`/proc/net` 里其它进程占用比对（dnsmasq、UPnP、DHCP），红色标注"该端口已被 X 占用" | 小 |
| 3-3 | **WAN 侧自测** | Test 按钮除了 dial 目标，再从本机 connect 自己的 listen_port，验证 fw/监听是否真的通 | 小 |
| 3-4 | **批量操作** | 多选 enable/disable/delete/clone/导出所选 | 中 |
| 3-5 | **规则模板库** | 一键模板：WireGuard UDP、SRT/SRTLA、NTP、游戏端口段、HTTPS 反代；带默认 family/fw/proxy 预设 | 小 |
| 3-6 | **每规则流量计数** | 从 conntrack 或 socat `-d`?（更实际：读 `/proc/net/nf_conntrack` 的 bytes/packets，或用 `nft` counter 方案）→ UI 显示 ↑/↓ | 中 |
| 3-7 | **旧配置迁移向导** | 检测到 `luci-app-socat` 风格字段/文件时，提供"导入并转换" | 小 |
| 3-8 | **i18n** | 字符串已包 `_()`，补 po 模板 + 中英双语 | 小 |
| 3-9 | **CLI** | `socat-reforged status/list/add/del/test`（人可读），方便脚本化与无 UI 排障 | 中 |
| 3-10 | **测试固化到 CI** | ① shell：`sh -n` + shellspec/bats 覆盖 `emit_section`/reconcile diff（用假 uci mock）；② UI：把现有 puppeteer 无头测试（pup/uitest*）搬进 CI；③ 后端：ucode 单测跑 `status`/`test` | 中 |
| 3-11 | **CI 收敛** | 4 job → 2 job（24.10-x86_64 + snapshot-x86_64），省 ~10 分钟；产物命名统一；加 `PKG_VERSION` 与 tag 一致性校验 | 小 |
| 3-12 | **CHANGELOG.md + 文档补强** | 版本变更记录；README 加"故障排查"章节（logread 关键字表：`No IPv6`/`bad listen_port`/`firewall synced`/`another engine loop`）、FAQ（端口不通的四步排查：规则 enabled? → listening? → fw 规则在? → 目标可达?） | 小 |
| 3-13 | **安全细化** | `test` 加频率限制 + 单次超时；ACL 维持最小化；`rule_restart` sid 白名单（已在 0-5 做） | 小 |

## 建议的版本切片

- **V3（建议）**：阶段 0 全部（0-1 ~ 0-8）+ P1-1 的错误上报骨架（1-1）+ P2-1 的 uci 单次解析（2-1）——这一版的主旋律是"**别人装上也能用**"和"**不再空烧 CPU**"。风险低、收益最大，且全部可通过 Router 实测验收。
- **V4**：阶段 1 剩余 + 阶段 2（事件驱动、日志分级、导入健壮化、端口聚合）。
- **V5+**：阶段 3 产品化能力（错误详情、系统冲突、模板、批量、i18n、CI 测试固化）。
